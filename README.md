# 投稿与审稿方法 Skills

七个面向人文社科作者的改稿、投稿和返修方法，适用于能读取本地文件的 Codex / Claude Code 等执行环境。发布版本 1.0.1。仓库：[qiaomiaojoe/ai-submission-review-skills](https://github.com/qiaomiaojoe/ai-submission-review-skills)，可见性为私有。

## 方法清单

| Skill | 用途 |
|---|---|
| `submission-task-intake` | 在投稿、改稿或返修任务开始时核实项目、匿名任务、材料版本与作者批准范围，形成任务登记并交接给当前业务场景。无需单独运行入口卡。 |
| `manuscript-diagnosis` | 对人文社科初稿进行论证和证据诊断，输出带原文定位、稳定问题 ID、修改建议及作者决定的诊断表，交接给批准范围内的改稿。 |
| `manuscript-revision` | 依据明确批准的问题清单修改人文社科稿件，保留核心观点、逐项修改对照和未完成项，形成待作者确认的定稿候选。 |
| `journal-requirements-check` | 从作者指定期刊的实际可读要求提取来源、适用范围、强制或建议和差距，形成可追溯要求矩阵；支持首次投稿与返修提交。 |
| `submission-package-preparation` | 依据作者确认稿、期刊要求矩阵与真实声明事实整理投稿稿、投稿信和核对清单，支持返修包，保留缺项及实名外部补齐状态。 |
| `review-response-planning` | 保留编辑与审稿意见原文，拆分稳定意见 ID 和子项，提出证据需求及回应方案，形成作者逐条决定台账后交接返修。 |
| `review-revision-response` | 依据已确认审稿台账和真实证据落实返修，再读取实际修订稿写逐条回复，核对意见、改动、位置与未完成项。 |

## 取回和使用

由执行 AI 用 git/gh 将本库克隆到新的空目录，核实当前版本及文件完整性，再将七个完整目录放入论文项目的 `skills/`。同名目录先比较，内容不同请用户选择跳过或更新，更新前保留备份；不自动覆盖全局或其他项目定制方法。

六个业务方法依赖 `submission-task-intake`，每个方法还读取自己的 `references/source-basis.md`；不要只复制单个 SKILL.md。首次使用可告诉执行 AI：“先核实我的论文项目根目录，实际读取 skills/submission-task-intake/SKILL.md 和本次场景的 SKILL.md 及其支持文件，再按我的材料和批准范围执行。”

本库只含方法。稿件、原文、期刊要求、审稿意见及作者决定由用户在自己的项目中提供。AGENTS.md、CLAUDE.md、投稿与审稿规范.md 指当前项目的规则文件；缺少时如实指出，依据该方法的缺项规则处理，不能凭文件名脑补。本库不附原作者的项目指令全文、论文材料、工作台 HTML、日志或测试产物。

本地业务结果按方法约定写入 `产出/<任务标识>/`，日志在用户项目中产生，均不应提交到方法库。引用作者姓名保留，其他真实姓名和学校按项目约定匿名；不编造来源或声明事实，观点和回应立场由作者决定。

## 私有库与新设备

本库为私有库。新设备先由执行 AI 检查 Git/gh，再发起 `gh auth login`；用户只在 GitHub 自己的授权页面登录具备仓库访问权的账号。授权后执行 AI 运行 `gh repo clone qiaomiaojoe/ai-submission-review-skills`，在空目录取回并逐文件核对。没有访问权的机器无法取回私有库，不能把本机认证、token 或密码复制进文件。无需将私有库改成公开来安装。

## 验证边界

1.0.0 项目版已做 YAML/结构检查、工作台生成机制和当前 Codex 顺序处理模拟材料及关键边界；真实学术业务未测试。1.0.1 仅作发布整理，执行方法沿用 1.0.0。发布时另以空目录取回进行文件、名称和版本一致性核验；仓库取回不代表真实业务验收。
